# vectorPath 运行性能与内存优化计划书

日期：2026-09-23

代码基线：`035e870730cc7cb3e5e69dfb17f3047254be91fb`

状态：算法优先修订版，待实施；本次交付为计划文档。

范围：现有二维 CAD/CAM 功能、文档事务、撤销重做、交互绘制、导入与恢复保存。

## 1. 项目目标与当前结论

本轮目标是降低大图编辑的等待时间、鼠标操作延迟和运行期间的内存峰值，让优化能在真实操作中被感知。

当前已经实现部分运行优化，但尚未完成整条操作路径的性能治理。尤其是：
提交阶段的批量删除已优化，事务准备阶段仍按每个 ID 扫描全部实体；普通历史项已去掉
无用的全量 ID 顺序数组，但历史条数和保留字节数没有上限；绘制、拾取、捕捉仍存在
全量遍历和重复几何构造。因此，目前不能宣称应用整体已经明显提速或运行内存已下降某个比例。

上一轮清理释放约 1.30 GiB 的是本机构建产物占用的磁盘空间；它不构成本计划的运行内存成果。
命名统一、无 Qt 核心拆分和减少测试项目是工程组织改进，运行收益仍须单独测量。

本计划采用“测量算法工作量 → 降低重复扫描与候选规模 → 控制保留内存 → 验证真实操作”的实施顺序。
第一批优先处理批量查询、全框选去重、路径阵列定位和单线填充；空间索引、刀路查询与偏移粗筛紧随其后。
减少深拷贝及历史预算仍保留为内存支线，不替代算法阶段的验收。
优先改动现有模块，普通测试继续使用现有两个测试程序，不为每个优化项新建目录、库或测试工程。
三维 P3 保持暂停，也不恢复用户此前要求删除的 CAD 功能。

### 3.1 算法主线与复杂度变化

本次修订将算法工作量作为主线，内存副本、缓存及后台执行作为配套。
移动语义只降低单次复制成本，缓存只减少重复执行，线程只改变并发方式；
如果仍逐个扫描全部候选，就不能宣称算法已经由二次复杂度变成线性。

下面的成本来自当前循环与数据结构分析，省略几何载荷复制；哈希的线性界均指平均情况。
N 为文档实体数，K 为请求/选中数量，P 为路径段数，I 为阵列位置数，
E 为边数，L 为填充扫描线数，aᵧ 为当前扫描线活动边数，
M 为刀路数，G 为图层数，C 为粗筛候选数，V 为树节点访问次数。

| 算法项 | 当前工作量 | 拟采用的方法与成本 | 性质 |
| --- | --- | --- | --- |
| A1 批量查询与选择去重 | 事务 O(NK)；全框选的去重最坏 O(N²) | 请求/成员索引加一次扫描；平均 O(N+K)，保留原顺序数组 | 明确消除重复全扫描 |
| A2 路径阵列定位 | 每个位置从头找段，O(PI) | 累计长度单调游标，定位总计 O(P+I)；任意独立查询用二分 O(log P) | 定位阶段的渐进复杂度改善 |
| A3 单线填充 | O(LE + Σ aᵧ log(aᵧ+1)) | 边事件表与活动边表：O(E log E + L + Σ aᵧ log(aᵧ+1)) | 消除每条扫描线对全部边的重复判断 |
| A4 拾取/可见区域查询 | 每次遍历全部实体及相关几何 | BVH 构建 O(N log N)、空间 O(N)；查询成本为 V+C 加精确判定及输出 | 减少候选，稠密退化时仍可线性 |
| A5 刀路分组与最近邻 | 分组 O(MG)，逐层最近邻 Θ(Σ m_g²) | 有序分组映射；活动端点空间查询减少每步距离计算 | 分组平均线性；最近邻不承诺最坏阶数改善 |
| A6 偏移路径自交清理 | 最多 16 轮，每轮 O(E²) 对段判交 | 线段包围盒粗筛后保留原精确判交；计构建、V、C、候选保序与修改成本 | 稀疏场景减少求交对；最坏仍可二次 |

上述“定位、去重、候选查询”都是阶段成本，生成 I 份实体、输出 K 个选择结果或绘制可见几何的
必要工作仍须完成，不能把阶段复杂度写成整条操作的复杂度。

**A1：批量事务与全框选先做。**

事务实现见第五节；[selectInWindow](../sgraphRender/vp_cad_viewport_selection.cpp)
目前每命中一个实体，都在不断增长的已选数组里执行 std::find。
唯一 ID 的 N 个实体从空集全部选中，单去重就可能进行 N(N−1)/2 次比较：
N=100,000 时约为 50 亿次。该计数尚未包含包围盒与图层查询。
新增成员集合用于判重，顺序仍由原数组保存；即使全图都可见、空间索引无法剔除实体，
该项也能将去重的平均工作量降至线性。重复 ID、追加选择与隐藏/锁定规则保持。

**A2：路径阵列使用单调累计长度定位。**

[pathArrayEntities / pointOnPath](../sgraphRender/vp_cad_viewport_array_path.cpp)
已生成各段累计长度，但每个阵列位置仍从第一段 find_if。
阵列的目标距离按 item×spacing 单调增加，因此游标只需向前推进；
P 段、I 个位置总计推进不超过 P 次，并处理 I 次定位。
P=I=10,000 时，原定位最坏上限约 1 亿次段判断，新路径约 2 万步量级；
这是工作量分析，尚非实测速度，实体变换与生成成本另计。
保留原有零长段过滤、1e-9 比较、折点采用哪一段切线、开闭路径端点和当前 10,000 项限制；
本项不顺便增加弧形路径支持。

**A3：填充改为事件驱动的活动边表。**

[scanEvents / createSingleLineFill](../sgraphIo/vp_vector_fill.cpp)
目前每条扫描线都访问所有轮廓边，然后对有效交点排序。
预处理每条非水平边的进入/退出事件，扫描线推进时只加入新边、移除结束边，
仅对活动边计算交点。第一版继续逐行排序活动交点，避免同时改变复杂的自交排序规则。
保留原 y 采样序列、[minY,maxY) 半开条件、EvenOdd/NonZero、winding 累计和同 x 容差分组；
先用原公式计算交点，不通过持续累加 x 引入漂移。
当少数边跨越当前扫描线时收益大；若每条边横跨几乎全部扫描线，活动边数接近 E，
最坏阶数未必改善。报告空行、孔洞、密集交叉和旋转后的退化样本。

**A4：空间索引的收益来自排除不可能命中者。**

按第七节的保守边界建立二维 BVH，先做范围/距离下界筛选，再调用原精确谓词。
V、C、精确几何调用次数和重建耗时必须计入结果。长条包围盒、全重叠、
极端缩放和查询覆盖全图时 V、C 可达到 Θ(N)。
需要文档顺序的候选，小集合排序需计 O(C log C)，大集合改按文档次序扫描/标记，
避免全选反而增加排序成本；输出本身有 Ω(K) 的工作量下界。
无限延伸、平行等捕捉继续使用适用的完整候选或另行验证的查询方法，
不能直接套用局部实体包围盒筛除。

空间层级与距离查询机制可参考
[CGAL AABB Tree 官方说明](https://doc.cgal.org/latest/AABB_tree/index.html)。
该参考说明的是有限几何查询方法，不构成引入 CGAL 依赖的决定；
本项目的增量失效、内存预算和顺序语义仍需自行设计验证。

**A5：刀路排序分成整条调用链治理。**

[shortestSort](../sgraphGeometry/vp_toolpath.cpp) 是最近邻贪心：
每选择一条刀路，就重新扫描所有剩余刀路。
[sortDocumentToolpaths](../sgraphDocument/vp_toolpath_document.cpp) 还包含线性分层、
逐条反向替换及全体重排。设 R 为实际反向数，忽略复制后的整条成本约为
O(N + MG + Σ m_g² + RN + N log N)，不能只优化中间的距离计算。

先用“首现顺序数组 + 名称到组号映射”分组；唯一 ID 的指定顺序用经校验的排列置换，
哈希方案平均线性，重复 ID 回退当前稳定排序语义；反向替换接入 A1 批量事务。
随后用起终点活动索引进行最近候选查询，选中实体后使其全部端点失效，
并维护活跃计数/适时重建，避免反复访问已删除点。
常见低维分布的目标是接近 M log M 的查询总成本，但重合点、容差竞争、
不利分布及回退可能使总工作量仍为二次。

当前比较规则是 candidate_distance+1e-12<best_distance，且按原顺序扫描，
不是普通的“最小距离加 ID 打破平局”。以 epsilon 为单位，
距离序列 [2.2,1.3,0.5] 完整扫描选择 0.5；只取最小值附近 epsilon 范围再重放，
却可能在 [1.3,0.5] 中选择 1.3。原型须使用可证明等价的顺序感知剪枝，
或只在最优/次优有效候选明确分离时采用加速结果，存在近距离竞争则回退原扫描。
保留每条刀路是否允许反向、起终点偏好和跨图层衔接规则。

空间树会因分割方法和数据分布发生退化，不能统一承诺每次查询 O(log M)；
见 [CGAL 空间搜索官方说明](https://doc.cgal.org/latest/Spatial_searching/index.html)。
此处只是加速同一贪心结果，不证明刀路总空移距离更短，更不代表求得全局最短路径。
若另行研究刀路质量，可试验有约束、限时的局部改良，并分别报告空移长度与计算耗时；
改变加工顺序的方案不混入默认兼容路径。

**A6：偏移消环先减少求交对，保持选环规则。**

[removeOpenPathLoops / removeClosedPathLoops](../sgraphRender/vp_curve_offset.cpp)
目前每轮按 (first_index,second_index) 搜索首个交点，然后删段/选环，最多 16 轮。
新增线段 AABB 粗筛，仅将可能重叠的非邻接段交给原 segmentIntersection；
仍按原 (i,j) 字典序选首个真实命中，保留闭环首尾排除、容差、面积并列和 keep_larger_loop。
每次改动后重建或准确更新段索引，禁止使用已经失效的段号。
每轮计 O(E log E) 构建、访问节点总数 V、候选对 C、候选保序以及结果修改；
若通过排序恢复候选次序，另计对应排序成本，不能在复杂度中省略。
长斜边/密集自交可能产生 Θ(E²) 候选，不能写成只与真实交点数量相关的成本。
候选按需访问，不为粗筛一次性分配全体 E² 对。

**暂不重复立项的算法。**

位图相邻行连接已经使用双指针，连通块已有并查集；偏移中的样条已经自适应细分，
线圆/圆圆求交已有解析实现，多边形布尔已调用 Clipper2。
这些保留为现有能力。位图整数键基数排序、JOIN 端点网格和新的刀路局部改良列为后续候选，
仅在上述主线测量后证明其必要性时进入实施范围。

## 4. 先建立可复现的基线

### 4.1 测量口径

以当前基线提交为“下一阶段优化前”，后续每批改动使用相同机器、输入和构建选项比较。
主性能数据使用 x64 Release；Debug 用于正确性验证，x86 Release 验证兼容性和受限地址空间。
不混用不同配置、不同输入或不同硬件的结果。

每份结果记录提交号、CPU、内存、GPU/驱动、系统版本、Qt/编译器版本、线程数、
窗口尺寸和 DPI、输入文件校验值、实体数及总顶点数。首次打开和已预热场景分别统计。
普通操作至少预热 3 次、测量 20 次；鼠标轨迹采集至少 1,000 个固定输入点，
记录中位数和 P95。P95 表示 95% 的样本不超过该耗时。
大型一次性导入每个场景至少使用 5 个独立进程样本，报告全部样本及中位数，
不对少量导入样本给出有误导性的 P95。

必须同时区分：

- 完整操作时间：请求进入命令，到事务完成、相关状态通知结束，再到包含本次文档版本的首帧交换完成。
- 阶段时间：查找、暂存、提交、历史处理、索引重建、捕捉、绘制命令提交、文件解析。
- 内存：进程私有提交量、当前工作集、峰值工作集、采样峰值私有提交量。
- 应用内部统计：活动文档、历史、缓存、预览、导入中间结果的保留字节及容器容量。
- 复制指标：实体复制次数、几何复制字节；它们是工作量指标，不冒充内存峰值。

`paintGL()` 内的 CPU 计时不等于 GPU 完成或屏幕呈现时间；绘制提交和帧交换分开记录。
计时以操作序号及文档版本关联到实际绘制该版本的帧，不能误取上一次操作的帧。
`QOpenGLWidget::frameSwapped` 只作为应用可观测的交换完成代理指标，
不宣称测到了显示器上的物理呈现时间；各版本比较使用同一结束事件。
操作系统工作集受内存管理影响，关闭文档后主要验收内部所有权释放与私有提交量趋势，
不要求工作集立即归零，也不通过强制清空工作集制造“内存下降”。

现有位图基准的 `PeakWorkingSetSize` 是进程生命周期高水位，且基准会同时持有不同算法结果。
对比算法内存时改用独立子进程测量，并分离输入、结果、校验与工作缓冲；
不可直接用现有单一峰值推导某个算法的内存降幅。

### 4.2 固定场景

| 场景 | 建议输入 | 操作 |
| --- | --- | --- |
| 小图回归 | 1,000 个混合实体 | 打开、单选、单实体修改、保存 |
| 批量编辑 | 10,000 / 100,000 实体；删除比例 1%、20%、100% | 删除、替换、改图层、改线宽、撤销、重做 |
| 稀疏大图 | 100,000 实体；视区覆盖约 1% 和 10% | 平移、缩放、点选、窗口选择、连续捕捉 |
| 重几何 | 10,000 曲线，含大多段线、多岛填充和 1,000 个多行文字 | 重绘、样式变化、选中、预览 |
| 历史压力 | 固定大图连续 1,000 次编辑，并执行撤销/重做分支 | 观察历史与进程内存走势 |
| 导入 | 固定 DXF/SVG；4096×4096 位图含大色块、棋盘格、离散颜色及透明像素 | 解析、矢量化、事务提交、取消、保存 |
| 生命周期 | 连续 100 次打开、预览、取消、关闭 | 检查残留引用、缓存和后台任务 |
| 极限压力 | 1,000,000 个简单实体，仅 x64；x86 以实际内存预算限额为准 | 找出退化点、记录失败方式，不先承诺流畅 |

总顶点数、文字长度、填充边界复杂度必须记录，不能只拿实体数量解释内存。
原始计时、采样和生成样本放在 `build` 内；使用已有测试和可选基准设施，不增加普通测试工程。

### 4.3 算法验收增加工作量计数

算法阶段同时报告“输入规模 → 基本操作次数 → 运行时间”，不只测毫秒或复制字节。
先用轻量实体隔离算法本身，再用重几何测完整操作。各样本的输出数量也要单独记录。

| 算法 | 固定与增长的维度 | 计数/验收 |
| --- | --- | --- |
| A1 | N 等比增长，K 分别固定及占 N 的 20%/100% | 全文档扫描次数、ID 比较与成员探测；唯一 ID 全选不再执行 N(N−1)/2 级别线性判重 |
| A2 | P 与 I 分别增长，I 遵守现有 10,000 项上限 | 单次阵列段游标推进最多 P 次、定位 I 次；位置、切线与输出顺序逐项一致 |
| A3 | E 与 L 分别增长；稀疏边、跨全高边分组 | 边入表/出表各至多一次，交点计算按实际活动边累计；逐条比较填充线段 |
| A4 | 稀疏、重叠、长条、全可见场景分开 | V、C、精确判定次数、顺序恢复成本、建树与更新次数；稀疏大图目标精确判定减少至少 90% |
| A5 | M 增长；G=1、10、M；随机/网格/密集/重合/容差链 | 各步端点距离计算、树访问、失效点跳过、完整回退比例、维护时间；逐步选择、方向与最终顺序全等 |
| A6 | 展平后 E=100、1,000、10,000，稀疏/密集自交分开 | 粗筛比较、候选保序、精确求交次数及轮数；稀疏路径目标精确求交减少至少 90%，原输出点列一致 |

规模翻倍时检查计数如何增长，并连同时间分布解释；不能仅凭一次耗时比就断言复杂度。
计数器在可选基准中启用，不能为了验收让正式应用每次几何计算都承担昂贵追踪。
空间算法必须报告冷构建、热查询和每次修改后的维护总成本。
默认兼容算法必须与旧路径等价；会改变结果质量的独立试验另报空移长度、拓扑或误差，
不能与“同结果加速”的数据合并。

## 5. 第一批：优化完整事务路径

### 5.1 批量查询与暂存

1. 在现有 `VpDocumentTransaction` 增加批量删除、替换和属性修改路径。
   先建立本次 K 个请求 ID 的临时索引，再扫描一次 N 个文档实体，最后按原请求顺序处理。
   临时索引仅服务当前调用，预计准备阶段由 O(N×K) 降至平均 O(N+K)，辅助内存 O(K)。
2. 暂存区如需按 ID 多次查找，维护“ID → 首个暂存位置”的索引；追加时更新，
   提交或销毁时释放。索引保存位置，不保存可能因数组扩容而失效的裸指针。
3. 暂不为整个文档无条件增加常驻哈希表。跨操作 ID 索引只有在测量证明确有收益后启用，
   并记录内存代价；x64 下 ID 和位置本身就需要约 16N 字节有效载荷，哈希桶、节点及分配器另计。
4. 已知批量数量时合理 `reserve()`；把只使用一次的非 const 暂存表移动交接，
   保留容器适度复用。不在每次操作中无条件 `shrink_to_fit()`。

重复请求、缺失 ID、异常重复文档 ID、混合增删改及交错事务，都先用当前行为建立对照。
批量接口接入原命令入口，不能只优化一个没有真实调用者的辅助函数。
不得改变撤销粒度、图层规则、实体顺序、返回结果和通知语义。

### 5.2 发布准确的变更范围

事务提交、撤销、重做产生一次有序变更描述，包含新增、移除、几何变更、属性变更、
顺序变更和图层/样式变更。现有 Qt 通知继续由桌面层发出。

第一版可只增加版本号并整体失效，确保正确性；有完整变更描述后才逐步做增量更新。
所有写入口都必须覆盖，包括图层修改、审计修复、加载、清空和撤销重做。
没有变更信息的路径回退到整体失效，不能猜测哪些缓存仍然有效。

### 5.3 顺序调整

刀路排序和纯重排过程优先传 ID/位置索引，避免搬运完整几何。
顺序应用比较“校验后的排列置换”与当前 `stable_sort`；只在保持重复 ID、
既有稳定顺序和异常处理语义的前提下替换。方向反转等真正修改几何的操作仍保留必要版本。

本批验收：每个批量请求至多扫描全文档一次；未修改实体不被复制；纯顺序操作不复制几何；
完整删除/替换路径的耗时和峰值内存同时报告。

## 6. 内存支线：控制撤销历史和几何复制

### 6.1 先做字段差量

现有历史已经按事务记录新增和移除实体，不能再泛称“从整文档快照改成增量历史”。
下一步针对剩余粗粒度记录细化：

- 修改实体图层或线宽：保存实体 ID、旧值、新值和必要位置，避免复制多段线或填充几何。
- 修改图层、文字样式、标注样式：保存变化的表项及原位置；单纯切换当前样式只保存名称。
- 几何变化：继续保留撤销所需几何版本；新增、删除和替换使用各自的历史记录类型。
- 关联阵列、图层合并等复合操作仍作为一个原子事务，不以节省内存为由拆成多个撤销步骤。

### 6.2 再评估大几何的所有权

在字段差量通过后，选择一种重几何场景做小范围原型，比较：

- 历史只保存非活动版本，撤销/重做时在当前文档与历史之间移动或交换载荷；
- 仅大几何采用不可变共享载荷，编辑创建新版本，历史共享未改变的数据。

优先使用最少改动即可消除实测重复副本的方案。多步历史会再次引用同一实体，
不能只把当前 `insert` 改成移动后就清空后续撤销所需的数据。
共享方案也必须验证引用计数、版本失效、修改入口和小实体开销。
未经原型证明，不把全体直线、点和实体记录都改成共享指针。

移动/交换原型先限于 ID 唯一、同一事务对同一实体至多一次几何更改的路径。
重复 ID 或同事务重复触达实体暂用现有快照语义回退，除非已经引入并验证稳定实例身份；
不得静默去重。提交、撤销、重做都先完成必要分配及合法性检查，再执行破坏性移动，
确保失败后文档、历史载荷和历史游标保持原样，并增加分配失败注入测试。

### 6.3 历史预算及产品行为

增加历史保留字节、条数和超限状态统计，所有历史入栈统一登记。
估算包含动态几何数组、关联阵列源、字符串、样式表和容器容量；
共享载荷按实际持有关系计费，避免重复计算。统计值明确标为估算，与进程数据并列报告。

建议初始配置如下，数值在基线阶段校准，均尚未实现：

| 项目 | x64 建议值 | x86 建议值 | 规则 |
| --- | ---: | ---: | --- |
| 单文档撤销/重做合计软预算 | 256 MiB | 64 MiB | 两个栈合计计费，不能只限制撤销栈 |
| 单文档历史条数 | 1,000 | 1,000 | 按完整事务计数 |
| 全进程历史合计软预算 | 512 MiB | 128 MiB | 多文档共同计费，不让每份文档各自无限扩张 |

超限时只从不破坏依赖链的边界淘汰完整记录：撤销栈删除最旧的已应用端，
重做栈删除最远的未来端；不能删掉下一步重做却保留依赖它的后续步骤。
使用便于边界淘汰的容器；移动版撤销/重做会交换历史持有的载荷，版本转移后重新计费。
保留最近一个完整操作；若单步本身超过软预算，则保留该步并显示超限，
同时不再保留可淘汰的更旧历史，不能承诺此时仍满足软上限。
若无法在当前内存条件下安全准备一次操作，则在修改活动文档前失败返回。

历史限制会缩短可撤销范围，属于用户可见的行为变化，界面必须显示可撤销范围及超限原因，
并提供预算设置；不能静默丢弃仍在范围内的历史。
新操作清空重做分支的既有规则不变。多文档淘汰须明确指示受影响文档，
全进程预算仍遵守每个文档最新完整一步的例外。

### 6.4 关闭与清空

关闭文档释放文档、历史、场景索引、文字布局、预览源和相关任务持有的引用。
清空文档时检查并释放大容器保留容量，普通连续编辑仍允许容量复用。
验收内部统计与实际进程趋势，不以“调用了 clear()”作为内存已释放的证据。

## 7. 第二批：加速捕捉、绘制和预览

### 7.1 场景索引与保守视区剔除

在现有渲染模块维护派生场景数据：实体位置索引、已解析图层属性、选择集合以及包围盒树。
先以版本号整体失效、按需一次重建实现，再根据第五节的准确变更描述做增量更新。

索引由文档/视口生命周期管理，存实体位置与代次；删除、重排、换文档后旧位置立即失效。
绘制保持文档顺序；当前点拾取同距离优先后出现实体，按 ID 查找取首个匹配，
对象捕捉同优先级同距离保留先出现候选，优化后必须保留这些差异。

用于绘制剔除的包围盒必须保守覆盖真实线宽、文字、标注、弧形多段线及关联填充。
不能直接把现有近似选择包围盒当成绘制边界；暂时无法证明边界正确的类型回退到绘制。
窗口选择依赖缩放的最小范围也需保留。

捕捉只对可安全局部化的候选使用空间查询。无限延伸、平行、外观交点等情况不能
统一套用鼠标附近的实体包围盒过滤；未建立正确加速方法前保留完整有序候选。
保留现有线段和圆各 64 个邻近交点候选上限、最多 8 个追踪锚点及捕捉优先级。

### 7.2 有界几何与文字缓存

缓存键包含实体位置/版本、用途及影响结果的参数。
世界坐标几何不因单纯平移而失效；绘制、拾取和捕捉使用不同离散精度时分别缓存。
第一版保持现有精度参数，例如椭圆绘制/拾取与捕捉不能直接共用同一份不同精度折线。
样条绘制继续使用现有三次曲线路径，不为缓存而改成低精度折线。

优先缓存椭圆离散、宽多段线轮廓、填充路径和多行文字布局。
文字键包含内容、字体、样式、布局宽度、实际像素尺寸/DPI等；世界几何与屏幕布局分开。
关联填充在关联边界变化时失效；选择颜色或主题变化不应触发无关世界几何重算。
图层/样式修改、撤销重做、打开新文档、重排和字体/DPI变化均纳入失效测试。

建议全进程派生缓存软预算 x64 96 MiB、x86 32 MiB，多个视口共享总预算，
非活动视口优先淘汰。初始分配参考为索引约三分之一、几何/捕捉约一半、文字约六分之一，
以实际计费为准。大于预算的单个实体不缓存，直接计算；
LRU 只淘汰可重建结果，不能淘汰活动文档或必要事务数据。
空间索引无法完整容纳时，保留未索引实体的正确回退查询，不能漏选或漏画。

### 7.3 预览只描述变化

移动、复制、旋转、缩放、镜像及阵列预览优先使用“只读源实体 + 变换参数/实例”，
提交时才生成最终实体。夹点继续复用已有源快照，只更新受影响的预览数据。
不能简单整体缩放或镜像 QPainter 导致文字倒置、线宽变化等语义偏差。

修剪、圆角等非仿射预览缓存最新输入对应的计算结果；输入不变的重绘直接复用。
取消、完成、换工具、换文档时释放预览；大缓冲在命令结束时按预算回收。
不通过降低捕捉精度、漏处理最终点击、删减图形或盲目丢鼠标事件换取帧率。
Qt 已会合并部分 update 请求，应先测量实际重绘次数再决定是否增加额外调度。

## 8. 第三批：降低导入峰值并减少主线程阻塞

### 8.1 位图阶段内存

保留现有游程算法、并行阈值、确定性 ID 和规范化顺序。
先记录 rows、connections、原始边、压缩边、轮廓及 SVG 文本的存活时段，
在最后消费者结束后释放或移动交接，避免多个峰值阶段无谓重叠。

优先消除“轮廓 → SVG 文本 → 再解析为实体”的应用导入绕行：
直接把结构化轮廓转换为文档导入数据；需要导出 SVG 时才生成文本。
直接路径必须保留坐标、方向、孔洞、颜色、透明度、填充参数和图层映射，
与原链路进行逐项/哈希对照。显式导出 SVG 的既有字节确定性保持不变。

先消除对话框中不再使用的结果被 const 限制而发生的容器复制，并改为明确的移动交接。
现有 SVG 解析已经使用 QXmlStreamReader；需减少的是入口全量文本与重复点列，
不能把解析器本身的流式能力再算一次成果。outlines 与 regions 各有消费者，
如要共享轮廓必须核对两条用途，不能直接删掉其中一份。

仅在中间结构仍是主峰值时，进一步研究分行块处理和边界交接；
不能破坏跨块连通、孔洞或稳定输出顺序。线程数根据输入规模和临时内存预算选择，
不能简单叠加后台任务池与已有内部线程池造成线程过量。

### 8.2 DXF/SVG 和原生文件

DXF 从“全文件组码对 + 实体片段复制”逐步改为组码流读取和当前实体缓冲，
保留状态机处理表、实体边界、关联信息及错误行号；确需全局信息的表单独受控暂存。
DWG/DXF 适配过程另行核对两遍处理需求，不机械共用错误的单遍假设。

SVG 尽量通过输入设备流解析，避免入口 readAll 及重复文本转换。
原生保存已经使用 QSaveFile 和数据流，不再列作“新增流式保存”成果；
原生加载先改掉可移动的局部实体复制，但保留完整候选文档验证后才替换活动文档的原子性。
不能为了降低峰值直接清空当前文档再尝试读取新文件。

### 8.3 后台导入与恢复保存

后台只执行与界面无关的解析和几何计算，任务拥有明确的输入与结果。
工作线程不访问活动 QWidget，也不跨线程修改活动文档。
采用有界任务/结果队列和取消令牌；结果带文档身份及版本，旧文档结果不得回填新文档。
提交前再次检查状态，按单个事务完成；超大提交若仍阻塞，后续在独立暂存文档中准备，
发布时原子切换，不能把未完成的半个事务暴露给用户。

自动恢复首先避免无变化的重复写盘：记录完整内容版本和最后成功恢复版本，只有新增版本
才生成恢复副本。实体、图层、样式、撤销/重做等内容变更均须提升版本；
isModified 或 modifiedChanged 不能代替内容版本，持续已修改时仍可能发生新的变更。
写盘失败不推进“最后成功恢复版本”，保留重试能力；相同版本不重复写属于单独验收项。

自动恢复目前同步调用保存。后台化必须使用一致版本的只读快照或稳定分块版本；
不能将活动文档引用直接交给线程，也不能默认再复制整份大文档而不测峰值。
同一文档最多一个恢复任务，新增请求合并；成功落盘后才更新对应元数据，
失败保留原恢复文件。先验证任务取消、关闭文档和旧版本任务完成顺序。

## 9. 拟定验收指标

以下是建议工程目标，全部属于待测目标；不是已取得的收益，也不是所有图纸的统一承诺。
基线阶段固定输入与硬件后冻结目标；若某目标不适用，明确更新计划及原因，
不能悄悄更换更容易的样本。

| 项目 | 初步目标 | 必须同时满足 |
| --- | --- | --- |
| 批量事务 | 10 万实体、修改/删除 20% 场景，完整操作中位耗时下降至少 50% | 准备阶段至多一次全扫描；峰值私有提交量无明显回退 |
| 路径阵列定位 | 单次阵列段游标总推进不超过 P 次，并处理 I 次位置查询 | 对比所有位置、切线与生成实体；单独报告定位和实体生成耗时 |
| 单线填充 | 边入表/出表各至多一次，交点计算随实际活动边数量增长 | 原输出线段一致；分别报告少量活动边及全部边贯穿的退化场景 |
| 属性编辑历史 | 大多段线批量改图层/线宽的几何复制为 0；该场景历史保留量下降至少 60% | 撤销重做、顺序和通知一致 |
| 历史预算 | 1,000 次编辑后保留量遵守软预算及明确的单步超限规则 | 保留范围内的操作均可完整撤销；多文档合计受控 |
| 拾取/捕捉 | 稀疏 10 万实体固定轨迹，点拾取与捕捉分别统计、各自 P95 耗时下降至少 60% | 两条路径各自逐点比较，ID、结果类型、坐标和优先顺序一致，不合并样本掩盖退化 |
| 大图绘制 | 视区约 1% 可见场景，绘制 CPU P95 下降至少 50% | 同时报版本对应的帧交换代理时间、冷重建与缓存字节；不漏画 |
| 预览 | 大选集/阵列场景，完整几何复制流量下降至少 80% | 最终提交与预览含义一致；取消后释放大缓冲 |
| 位图导入 | 固定大图集的导入峰值私有提交量中位数下降至少 25% | 包含解析、转换与提交；结果等价，时间不明显回退 |
| 生命周期 | 100 次打开/取消/关闭后，已关闭文档归属的缓存和任务保留量为 0 | 预热后私有提交量无持续上升趋势，分析分配器保留量 |

小图和普通单实体操作不得出现可重复的超过 10% 的耗时回退。
噪声附近的差异需重复独立测量确认；实测结果报告分布和原始数据，不仅给出最好一次。
除目标历史或临时副本被消除的场景外，不笼统要求所有操作内存下降；
索引和缓存可能增加保留内存，必须在预算内证明时间收益。

## 10. 正确性与交付门槛

每批以独立、可回退的提交交付，先小范围接入再替换实际入口。
建立短期旧路径对照或固定参考结果，验收完成后删除生产代码中的冗余重复实现；
正确性所需的回退路径保留，有意义的对照测试保留在现有测试设施内。

必须覆盖：

1. 混合实体与大几何的新增、删除、替换、属性修改、排序、撤销、重做和重做分支截断。
2. 缺失/重复 ID、空文档、全量删除、混合事务，以及已有“重排后新增实体”的边界。
3. 隐藏/锁定图层、同距候选顺序、极端缩放、长线延伸、超过 64 个邻近候选、
   文字/DPI/主题变化及关联填充边界变化。
4. 冷索引重建、热缓存命中、预算淘汰、单项超预算与强制不使用缓存时结果一致。
5. 导入损坏、取消、后台失败、关闭文档及恢复保存并发；失败后原文档仍完整。
6. 原生/旧格式、DXF/SVG/位图的适用一致性检查；已有二维功能与文件兼容行为保持。
7. 当前两个测试程序的核心与桌面套件；涉及位图时运行已有基准正确性检查。
   桌面 x64 Debug/Release、x86 Release 和无 Qt 核心的相应构建检查通过。
8. 每批 C++ 改动立即编译并启动应用；自研 C++ 每文件不超过 800 行，保持 Vp/vp_ 命名与代码风格。

截图验收遵守用户规则：由用户人工提供截图，工具不自动采集实际软件界面。
计时和数值对照可以自动执行；不能把进程启动或测试通过写成人工视觉验收通过。

相关功能范围按现有目录和差距矩阵核对：
ACAD.FILE.LIFECYCLE、ACAD.FILE.DWG_DXF、ACAD.VIEW.NAVIGATION、
ACAD.PRECISION.OSNAP/OTRACK、ACAD.MODIFY.TRANSFORM/ARRAY/GRIPS/OFFSET、
ACAD.LAYER.MANAGE、ACAD.CONTENT.HATCH。优化不得改变其当前功能边界或虚增完成状态。

## 11. 实施里程碑

| 阶段 | 交付内容 | 依赖 | 初步工作量 |
| --- | --- | --- | --- |
| M0 基线 | 固定样本、阶段计时、算法操作计数、分类内存统计 | 无 | 1–2 个开发日 |
| M1 确定性算法 | A1 批量查询/选择去重、A2 阵列双指针、A3 填充活动边表，接入真实入口并发布准确变更范围 | M0 | 3–5 个开发日 |
| M2 场景查询 | A4 保守空间查询、准确变更失效、保序和退化回退；建立必要缓存预算 | M1 的变更机制 | 4–6 个开发日 |
| M3 刀路与偏移 | A5 分组/排列/活动端点原型，A6 自交粗筛；含兼容与退化验证 | M1；M2 查询经验 | 3–6 个开发日 |
| M4 内存支线 | 字段差量、历史计费/预算、关闭释放、重几何所有权原型及预览去复制 | M1；预算行为明确 | 3–5 个开发日 |
| M5 导入与任务 | 中间结构释放、结构化导入、流解析、恢复版本去重及有界后台任务 | M0；状态一致性机制 | 3–5 个开发日 |
| M6 收尾 | 完整矩阵、长时间运行、算法/性能对照、清理旧路径与同步文档 | 所有已实施阶段 | 1–2 个开发日 |

按一条主实施线估计约 18–31 个开发日；这是包含算法原型和退化验证的初估，不是交付日期承诺。
评审和独立样本准备可并行，文档状态/事务所有权的修改避免多路同时进行。
M0 后按真实热点调整后续投入；若某个候选收益不足或内存代价过高，记录结果并停止扩展。

**首个可验收交付固定为 M0 + M1：**以批量查询、全框选去重、阵列定位和填充的
实际操作计数与端到端耗时证明收益。随后交付 M2 场景候选查询和 M3 刀路/偏移算法验证。
内存统计与预算约束贯穿全部阶段，历史所有权的大幅改造放在 M4，避免推迟确定性的算法收益。
GPU 渲染重写、全量 ECS/自定义内存池、全实体共享指针和全项目多线程改造均暂不立项；
只有前述阶段测量显示需要时，另行说明收益、代价和迁移范围。

每个阶段报告只包含：基线/当前提交、固定输入、正确性结果、操作时间、内存与复制指标、
已知退化、是否达到目标。已有进度文档统一记录结论，不为每次试验创建额外报告目录。
